## Behavior and data flow

Copies up to `0x20` bytes of a user name into a kernel stack buffer, then calls registry lookup `0x994d80(name, 0x110, &stored_name)`. Missing name/object returns 3. A found object has shared reference count +0x50 incremented while the registry lookup’s lock context remains active, then `0x994840` releases that context. A process-local handle is reserved and published using `0x399e00`. On success the handle is stored at `td + 0x408`. Handle allocation failure returns `0x23` and reacquires the registry context to undo the reference; zero remaining references free the name/object.

Review rollback under handle exhaustion and concurrent last close/delete. The input is a user string, not a pointer to a kernel object.

This is static analysis of a recorded kernel image. A missing check in this body does not establish that the syscall entry path, object namespace, or external callees impose no checks. Review points are not confirmed vulnerabilities or exploit primitives. No target code was executed.
