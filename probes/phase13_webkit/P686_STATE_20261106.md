## Critical bugs found this session

1. **Byte-order bug (affects p685 + all pre-3.5 forges).** The forge loop
   wrote the MSB-first hex string into `v[0x68..]` — on the little-endian
   PS5 the engine read `0x58a77e0010000000`-class NON-canonical garbage
   instead of the intended `0x10007exxxx` pointers. Every forge-based
   conclusion from p685 ("7/7 die on +0x28..+0x50", "delta-0 exact impl
   respected") is an artifact of garbage pointers, NOT slot semantics.
   Correct encoding: `hx.substr(16-2*(b+1),2)` (LSB first).
2. **Recycled-AB contamination (v5 fix).** Fresh 192B ArrayBuffers recycle
   memory of previously walked chunks carrying their engine writes/forge
   bytes at +0x58/+0x68. The v5 prime death rate (~50%, all inside the
   walk window) was the walk consuming OUR leftovers. v5.1 zeroes every
   AB in every mode; primes restore the natural face shape.
3. **Stale-key + position confounds (v3 fix).** localStorage values of
   dead processes must be invalidated (`/p686state` death detection) and
   census loads must alternate prime/arm so every observation is
   arm#1-class (2nd consecutive UAF load in a process is content-blind).
