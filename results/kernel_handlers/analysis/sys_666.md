## Observed behavior and functional interpretation

The syscall wrapper at 0x3b1680 loads an input pointer, a 32-bit count, and an output pointer from argument slots +0,+8,+16, then tail-calls 0x3b16a0. The implementation copies an array of 32-bit encoded handles, resolves per-process objects, updates operation status and completion state, and copies one 32-bit result per requested element back to the caller. The diagnostic string at kernel-data RVA 0x1350787 is _aio_multi_cancel, corroborating asynchronous-I/O cancellation; this is a string-derived name, not a binary symbol.

This description follows the target and the explicitly named linked helpers. Other functions in the attached carrier are adjacent context and are not silently attributed to this syscall. Code observations below are anchored by `ev_17b17cebcfb118e52280c78ae3a7db27fbbb625112b58ba15f22ed2d764d740b` and the individual helper evidence in the inventory.

## Dispatch, branches and result semantics

There is no caller subcommand switch. The count is restricted to 1..128 (0x3b1798..0x3b17d4). Each handle is split into a nonzero low 16 object identifier and a signed high 16 slot index constrained below 128 (0x3b1945..0x3b1968). Object slot count and null slots are checked before use. Per-item failures include 0x80020003 and 0x80020001; existing object states 3/4 are passed through (0x3b1b6c..0x3b1ba8). Eligible entries with state 1 are sent to 0x3b4190 with mode 1, remaining counters are decremented, dirty/completed fields are updated, and dependent waiters are walked (0x3b1c20..0x3b1d5d).

## Permission and state gates

The implementation selects a context from process-associated state obtained through 0x9f8180/0x9f81c0 and checks context+0x4a0, calling 0x3b3410(1) when needed (0x3b16df..0x3b1798). Handles are resolved through process+0xc48 using 0x399ee0, and 0x399e20 is a further per-object gate. Recovered 0x3b3410 initializes context queues, mutex-like objects and worker state, so it is an initialization/readiness gate rather than demonstrated credential authorization. The external helpers' policy is unknown; the observed checks do not establish a global privilege requirement or its absence.

## Dataflow, types and side effects

The count bounds both stack arrays (4*count) and the input copy at 0x3b1854. Optional tracing allocates 24*count bytes and fills a 24-byte record per item. Object+0x28 indexes slot pointers; slot+0x20 identifies the shared completion object. Final result copy is 4*count through 0x2591d0 at 0x3b1f6d. Context queues for classes 3..1 are drained under lock-like helpers 0x4c6a00/0x4c6fa0, and callbacks go through 0x3b4440.

## Attack-surface observations and unresolved contracts

Review boundaries are encoded-handle validation, object/slot lifetime, count-bounded stack storage, per-item error reporting, and completion/waiter updates across lock releases. This static slice does not establish helper locking contracts, object provenance, or a race or memory-corruption condition.

No exploitability finding is made. External helpers, unknown credential semantics, absent mutable data and upstream dispatcher behavior bound the conclusions. A missing check in this local slice is not proof of globally missing authorization. Static control flow does not prove any branch executed.
