===================================================================
Date: 2026-11-04 07:04
Probe: probes/phase13_webkit/p604-dfg-nan-confusion.html
Device: PS5 14.10 (192.168.1.37)

PURPOSE:
  Test whether DFG compileGetByValOnFloatTypedArray uses boxDouble()
  without NaN purification. Crafted impure NaN bit patterns should
  decode to null/true/undefined if the bug exists.

  Safe discriminator: vulnerable → non-number result; patched → NaN.

THEORY (Exodus Intelligence, Dec 2023):
  boxDouble() subtracts NumberTag(0xfffe000000000000) without checking
  for impure NaN. 0xFFFE000000000002 - NumberTag = 0x0000000000000002
  which JSC interprets as null (not a number).

=== VERDICT: NaN CONFUSION NOT PRESENT ===

  ALL 10 NaN bit patterns, across 5 different code paths (direct
  indexed, for...in Exodus pattern, forEach, pattern sweep, mixed
  warmup), returned NaN. Zero type confusion detected.

  The boxDouble() function in PS5 14.10 WebKit 605.1.15 purifies
  all NaN variants before boxing. Either:
  1. This WebKit version already had NaN purification in boxDouble()
  2. The EnumeratorGetByVal typed-array optimization doesn't exist yet
  3. Sony cherry-picked the fix (unlikely — no CVE, low profile)

  Explanation #1 or #2 is most likely: the Exodus bug was in an
  optimization added AFTER the 605.1.15 branch point. The for...in
  typed-array specialization in DFG was a relatively recent addition.
