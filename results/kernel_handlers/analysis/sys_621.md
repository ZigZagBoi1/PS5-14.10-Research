# Handler 621: static REA review

## Provenance and scope

- Original input: `handler_621.bin`, exactly 4096 bytes; SHA-256 `c22afc5c7cc3a6c3a1387f51b7dfa46b1ee55bb4b399853fd85ca6e05596c78e`. It contains 512 independent 8-byte trampolines. Only offset zero belongs to the requested syscall.
- Requested trampoline: runtime VA `0xffffffff8ac25760`, original kernel RVA `0x265760`; narg=0. Its jump target is `0xffffffff8af220e0` (RVA `0x5620e0`).
- Supplemental body reviewed: `[0xffffffff8af220e0, 0xffffffff8af22188)`, from supplied `kernel_text.bin` via analyst ELF. Original runtime base is `0xffffffff8a9c0000`; analyst ELF metadata/labels are synthetic. The target body is not inside the original input window.
- Review basis: static instruction/dataflow inspection of unchanged source bytes. REA root export is tracked in `rea_616_645_evidence/function_ffffffff8af220e0.json`; decompiler output is not substituted for byte-level evidence. No live kernel execution or dynamic security claim is made.

## Shared failure path with an observable side effect

Sysent metadata identifies this entry as using the shared nosys target. The supplemental root is **not** merely `return 78`: it constructs and submits a process/thread record before returning that error.

At `0xffffffff8af2210f` it derives `*(td+8)+0x148` and calls `0xffffffff8ae86a00(lock,0,0,0)`. It zeroes exactly 0x70 bytes at local base rbp-0x98, writes dword local+0x10=12 at `0xffffffff8af2212f`, and writes dword local+0x18=0x10006 at `0xffffffff8af22139`. The call at `0xffffffff8af2214f` is `0xffffffff8af20540(*(td+8),td,12,&local_record)`. It releases the same +0x148 object using `0xffffffff8ae86fa0`, checks its stack canary, and returns **0x4e**.

The process pointer, 12 argument, 0x70-byte zeroed record, and two explicit fields resemble signal delivery with signal 12. That interpretation is plausible but the callee has not been given a verified symbol; this report asserts the record data and call rather than a definitive signal name.

## Interface, errors, and attack surface

Metadata has narg=0 and args are unused. No subcommands, user-controlled pointer dereferences, output copies, or explicit permission gates appear. The submit callee's result is discarded, and 78 is returned independently. Stack failure calls `0xffffffff8b0bd6b0` then UD2.

A caller reaching the shared failure entry can trigger the fixed record submission against its current process/thread. Exact resulting signal/event policy requires callee analysis. This fixed side effect must not be generalized to neighboring trampolines or mistaken for a separate implementation for every metadata alias.

The normalized pseudocode and instruction listing were reviewed against the supplemental raw disassembly.

This is synthetic naming, not a different body or evidence that 621 invokes a separate 645 implementation. Its zeroed record fields and fixed return match the byte review.

Empty normalized callee lists do not mean no calls: unresolved call targets outside the selected ELF context still appear as address-labelled calls in the assembly.
