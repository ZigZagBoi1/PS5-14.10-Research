## Behavior and dataflow

Observed body `0xffffffff8b47d540`–`0xffffffff8b47d922` reads six argument slots: address `+0x00` (u64), length `+0x08` (u64), descriptor `+0x10` (low u32), protection `+0x18` (low u32), flags `+0x20` (low u32), offset `+0x28` (u64). It normalizes protection to its low byte when current-parent `+0x5d4 < 0x03000000`, validates inputs, selects an address hint and mode, then calls `0xffffffff8ad8b450` at `0xffffffff8b47d901`. The address variable is written to caller object `+0x408` even when this final call returns an error. A mapping-like wrapper is a strong inference from aligned address/length/offset inputs, VM-like bounds and address result; an exact syscall name is unproven.

At `0xffffffff8b47d62c` address must be 16 KiB aligned; length must be aligned and at least 16 KiB. Descriptor `-1` bypasses `0xffffffff8ad833e0`; other descriptors require its nonzero result. Protection must avoid mask `0xfffffc0c` (allowed mask `0x3f3`), flags avoid `0x009fdf2f`, and offset is 16 KiB aligned. Flag `0x40` requires length at most one page and protection low two bits nonzero. Flag `0x200000` requires nonzero `0xffffffff8b4e4300(current_parent)`.

## Dispatch and visible gates

There is no integer command switch. Flag `0x10` selects a fixed-address-like path at `0xffffffff8b47d7c4`: nonzero address, explicit addition-overflow check, and containment within `vm+0x20..vm+0x28`. Otherwise address is a hint, defaulted through `vm+0x1f8` or `vm+0x208`, with a special fallback `0xff0000000`. The mode selector is `flags & 0xff000000`: zero derives mode from `vm+0x244 & 2` and parent `+0x5d8`; `0x01000000` yields 1 or 3 from current-parent `+0xc81`; other values use `(int32_t)flags >> 16 & 0xffffff00`. The fixed path passes mode zero. Protection passed onward is `prot | ((prot >> 1) & 0x141)`.

Opaque gates `0xffffffff8afc9560(caller+0x140)` and `0xffffffff8afc95a0(current+0x140)` must return zero. A nonzero `0xffffffff8afc92d0(caller+0x140)` invokes diagnostic `0xffffffff8ac1d410` then returns 1. These look authority-related by use of the `+0x140` object, but privilege, credential identity and helper meaning are unknown. `0xffffffff8b478320(caller)` supplies a cookie classified by unsigned `(cookie - 0x7f0000000) < 0x800000000`; that classification and current-parent `+0xc81` change additional address/protection restrictions. Exact direct helper formulas are documented below; no known permission names are asserted.

## Returns and attack surface

Visible returns are 1 for initial gates, 22 for validation failures, and the delegated operation's integer result. The original ABI may conventionally name these errors, but numeric values are authoritative here. The principal surface is validated caller-controlled address arithmetic, flag translation, descriptor selection and delegation into an unreviewed helper. Only the fixed path visibly rejects address-plus-length overflow; the hint path performs wrapping comparisons, whose eventual safety depends on the delegate. This is a review point, not a demonstrated flaw. No caller buffer is directly copied by this wrapper. Stack-guard mismatch calls `0xffffffff8b0bd6b0` followed by UD2.

## Additional direct-helper evidence

A separate read-only disassembly of the supplied `kernel_text.bin` at `0xffffffff8afc92d0`–`0xffffffff8afc930f` establishes the predicate exactly: load u64 at argument-object `+0x58`; return one for `0x4800000010000004`, `0x4800000010000011`, `0x4800000010000012`, `0x4800000010000013`, or `0x4800000000001010`; otherwise zero. The first four are encoded as unsigned subtraction from `0x4800000010000004`, range 0..15 and bitset `0xe001`. This is an observed identity-value membership test. An auth-ID-like interpretation is plausible from its caller's `+0x140` object, but no external naming or ownership of those values was corroborated. These helper bytes come from supplied kernel text directly, outside the selected-body ELF.

Direct helper bytes `0xffffffff8afc9560`–`0xffffffff8afc957b` return one iff both `authority byte +0x6f & 0x40` and `authority byte +0x82 & 0x80` are nonzero. `0xffffffff8afc95a0`–`0xffffffff8afc95bb` instead require masks `+0x6f & 0x40` and `+0x82 & 0x40`. Therefore the wrapper rejects those exact paired-bit combinations in caller/current authority objects, respectively. Permission labels and bit meanings remain unknown.
