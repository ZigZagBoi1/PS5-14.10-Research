## Behavior and partial types

Body `0xffffffff8b47d930`–`0xffffffff8b47dac6` reads signed low u32 process-like ID at argument `+0` and signed u64 value at `+8`; value below 17 returns 22. ID zero or equality with current-parent u32 `+0xbc` uses that current parent and acquire-like `0xffffffff8ae86a00(parent+0x148,0,0,0)`. Other IDs require nonzero `0xffffffff8afc8f90(caller+0x140)` (zero returns 1), then `0xffffffff8aefc170(id)` (NULL returns 3). The lookup path joins with the target's lock-like member apparently already held; the helper's internals remain unknown.

The target partial layout is flags u32 `+0xb0`, state u32 `+0xb8`, ID u32 `+0xbc`, lock-like object `+0x148`, child pointer `+0x200`, and reference/count u32 `+0x358`. Flags mask `0x2200` must be clear and state must equal 1 or return 3 after release. It increments `+0x358`; when flag `0x10000000` is clear it calls `0xffffffff8aefaa10(target)`. It releases `target+0x148`, loads child `+0x200`, and, if nonnull, acquires child `+0x278`, stores the supplied u64 value at child `+0x280`, releases it and calls `0xffffffff8b051c70(child)`.

It then reacquires target `+0x148`, decrements `+0x358`, and if it becomes zero while target byte `+0xb1 & 0x20` is set, calls `0xffffffff8b5c6910(target+0x358)`. Final release and return 0 follow. NULL child therefore also succeeds without storing the value. The store suggests a configurable process/VM-like limit or parameter, but exact meaning and units are unknown.

## Gates, returns and surface

No selector switch or user-buffer copy is visible. Noncurrent targets have an extra opaque predicate; current-target access bypasses it. This is observed branch structure, not proof of a particular privilege policy. Return values are 0, 1, 3 and 22. Caller-controlled signed value, target selection, lock/refcount choreography, an unlocked child-pointer lookup protected by inferred reference machinery, and the post-store child helper are the main review surfaces. There is no explicit upper bound beyond signed 64-bit maximum, and helper effects remain unknown; neither fact alone establishes a flaw.

## Additional direct-helper evidence

Separate read-only disassembly of supplied `kernel_text.bin` at `0xffffffff8afc8f90`–`0xffffffff8afc8fa0` establishes its exact predicate: return `(u64(authority + 0x60) >> 62) & 1`, i.e. test mask `0x4000000000000000`. Thus this wrapper's gate requires that bit in the object reached through caller `+0x140`. The field's exact symbolic permission name and authority-structure identity are not corroborated. These helper bytes are supplemental source-kernel evidence outside the selected-body ELF.
