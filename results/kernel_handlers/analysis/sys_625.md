## Dispatch and coverage boundary

The root loads command32 at args+0, performs the unsigned range test `(command-1)<=22`, and otherwise returns **22**. Admitted command numbers are **1..23**. It loads index32 from args+0x10, sets the default status register to **6**, and jumps through signed relative-offset table **0xffffffff8c0e3560** at `0xffffffff8afc3cc5`.

The 23 table entries are beyond available kernel text/data. Selector-to-block mappings are **unknown**, including which in-range commands retain default 6. The semantic recovery therefore switches on the computed target address, not invented numeric commands. Available root code extends through 0xffffffff8afc4838; nearby functions at +0x4840, +0x4990, +0x49f0, +0x4b20, +0x4c50 are separate helpers.

Arguments occupy four 8-byte ABI slots: command32 +0, domain32 +8, index32 +0x10, raw value64 +0x18. No user pointer is dereferenced by the root, and value+0x18 is used as register data rather than an address.

## Hardware dataflow

The explicit x86 `rdmsr`/`wrmsr` instructions prove model-specific-register access. Bulk control operations read the six even addresses **0xc0010230, 0xc0010232, ..., 0xc001023a**. The enable block sets low32 bit 22 (0x400000), preserving other bits. The clear/reconfigure blocks compare each original register's low byte against 13 uint16 entries from unavailable table **0xffffffff8c0e35e0**. For matches they first write `(value & ~0xffff) | 0xa0`. They finally write each register with low32 masked by **0xffbf0000**, preserving high32. The intermediate writes matter even though later masks clear the low16 again. Comparisons retain the original low-byte values across the thirteen-entry scan, even after a matching register is rewritten.

The indexed counter-write block writes odd addresses **0xc0010231+2*index**; index -1 writes all six odd addresses through 0xc001023b. Domain bit0 triggers the first CPU group; domain>=2 triggers the second. The code locks current-thread state through `0xffffffff8ae878b0`, conditionally calls `0xffffffff8b0777c0(td,8)` when the first group is needed but current CPU (`gs:0x34`)<=7, or calls the same helper with 0 when the second group is needed but CPU>=8. It calls `0xffffffff8b077860(td)` after a change, then unlocks `*(td+0)+0x18`. The first-group change flag is carried into the second-group path, so a second restoration call can occur even if that second path did not itself request a change. This strongly suggests CPU migration/binding across two clusters, but exact scheduling semantics remain unknown.

Reviewed nearby helper **0xffffffff8afc4990** rejects `value & 0xe7fffff0ffff0000`. It writes index<=3 at **0xc0010240+2*index**, otherwise **0xc0010188+2*index**. The low32 payload is value low32; high32 is `(((value & 0x1800000000000000)*4)+(value & 0xf00000000))>>32`, including unsigned wrap semantics. It returns 0 after a valid write, otherwise 22.

Helper **0xffffffff8afc4c50** writes raw64 to odd counterpart addresses **0xc0010241+2*index** for index<=3, otherwise **0xc0010189+2*index**. Index -1 writes indices0..3 and additionally indices4..7 when the hardware-ID interval admits them. Helpers **0xffffffff8afc49f0** and **0xffffffff8afc4b20** respectively set and clear bit22 in the four base even MSRs 0xc0010240..0xc0010246 and, on the same hardware interval, the four extra even MSRs 0xc0010190..0xc0010196, bracketed by `0xffffffff8b062630/0xffffffff8b062650`. Helper **0xffffffff8afc4840** writes value to the selected even MSR 0xc0010230+2*index with the same domain/CPU-selection scheme; its own validation is not renamed as a known API.

## Permissions, errors, and attack surface

There is **no explicit credential read/test in this root** and direct hardware writes occur in its visible blocks. That does not establish all callers can reach all blocks: dispatcher policy is outside the target, and the missing table prevents definitive numeric command mapping. The software does restrict domain/index ranges and one helper filters value bits, while several visible paths write a full caller-controlled 64-bit value to a fixed indexed MSR.

Known local errors are 22 for invalid selectors/guards and default 6; helper returns propagate on tail-call paths, while void-like operations return 0. The root has no user copyout and does not write td+0x408. No stack protector is present. Hardware register access, CPU-binding transitions, and unknown helper effects are the evidence-grounded attack surface. No faulting MSR value, privilege bypass, or exploitable condition is established merely from the lack of a local credential test.

The normalized pseudocode and instruction listing were reviewed against the supplemental raw disassembly.

Ghidra reports an unresolved indirect jump and treats it as a call because the relative-offset table is unmapped. Its body address-set excludes the branch blocks behind that jump. Those blocks were separately recovered from the unchanged supplied target-context bytes and are described above by address; their selector mapping stays unknown. The manual semantic recovery preserves the missing-table boundary explicitly.

Empty normalized callee lists do not mean no calls: unresolved call targets outside the selected ELF context still appear as address-labelled calls in the assembly. Independent helper observations explicitly identified above come from `kernel_text.bin`, SHA-256 `406ab210236d4123e06495bcc8da82d8f89dac07266558dc8c0f80cc6cf55cf1`, and are supplemental byte analysis rather than claims of REA-provided symbols.
