=== ANALYSIS ===
ALL 5 sections survived forced GC at 200, 700, 1700, 2700, and 3700 t5 iterations.

Key: each forceGC() cycle (5000×128 objects) triggers collection that cleans up
dead resizable ABs from prior iterations. Each GC cycle only processes ~1000
accumulated dead ABs (between GC points), not the full ~20K that triggers the crash.

Compare: p608k crashed with ONE GC at 3850 (first GC, ~20234 dead ABs accumulated).
Periodic GC keeps the per-cycle dead AB count low, preventing the crash.

This confirms: the crash is NOT in DFG compiler output. The DFG-compiled code
runs correctly. The crash is a GC bug triggered by processing too many dead
resizable ArrayBuffers in a single collection cycle.
