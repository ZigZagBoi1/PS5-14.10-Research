--- ANALYSIS ---

The HABT bypass (CVE-2025-31277) is CONFIRMED but DFG JIT OSR exits are too
robust for direct type confusion attacks. Every test where we tried to make
DFG misinterpret an object as a double (or vice versa) resulted in correct
OSR exit behavior.

KEY FINDINGS:
1. Setter bypass is REAL (Section C) — objects stored directly in butterfly
2. Getter bypass is REAL for in-range indices (p637 P3)
3. BUT: delete creates holes that DO go through prototype (Section A)
4. Out-of-range accesses DO go through prototype (Section F)
5. ArrayStorage conversion FIXES the bug (Section H) — SlowPut activates
6. DFG OSR exits are correct in ALL tested scenarios

The HABT bypass does NOT give direct fakeobj/addrof via DFG profiling.
The exploitation path must go through a different mechanism:
- Invariant violation in JSC array operations that depend on HABT state
- Race condition between Contiguous→ArrayStorage conversion and another operation
- Finding a JSC code path that assumes setter fired but it didn't
