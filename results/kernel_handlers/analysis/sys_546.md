## Behavior and data flow

Looks up type 0x110 and calls `0xbaf710(object, argument_at_8)`, storing its low-32-bit result in a kernel local. It releases the lookup before optionally copying those four bytes to user pointer at +0x10. A null result pointer still performs the operation and returns 0. Missing handle returns 3. The helper updates/cancels the wait state and supplies the returned count; this count is not returned as the syscall status.

Recovered `0xbaf710` confirms that, unless the object has the closed/deleted attribute bit 0x1000, it replaces the pattern, snapshots +0x4c waiter_count, unlinks queued waiters, sets cancellation/wakeup flags and broadcasts. The pattern and waiter list are protected by the object lock. A closed object returns count zero without resetting it.
