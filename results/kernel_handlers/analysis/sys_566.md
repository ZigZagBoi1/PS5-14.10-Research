# Handler 566: Write saved performance-counter values

## Identity and scope

- Input: `handler_566.bin`, 4096 bytes, SHA-256 `22029bbda5344bf57db8e5fb34fdc2ab118c730a42f221802e4eae21fd57b088`.
- Verified exact match in `kernel_text.bin` at RVA `0x265de0`.
- First instruction: `jmp 0x603710`; next three bytes are `int3` padding.
- Sysent metadata: 3 arguments; mapping classification `real`.
- Runtime base from supplied context: `0xffffffff8a9c0000`; all addresses below are RVAs.
- Primary analyzed body (inclusive): 0x603710..0x603839, 0x603840..0x603887, 0x603890..0x6039c2.
- The full `.asm` covers all 4,096 source bytes, plus primary implementation and selected support. Neighbor trampoline targets are not part of this syscall.

## Behavior

Writes a uint64 value to PCB+0x190+8*index for one counter or to all six saved counter words if index == 0xffffffff. Enabled threads call 0x602e80, which programs the fixed odd-numbered MSRs 0xc0010201, 0xc0010203, 0xc0010205, 0xc0010207, 0xc0010209 and 0xc001020b, or synchronizes a remote running thread.

## Dispatch and subcommands

The low 32-bit selector is interpreted by an unsigned `(selector-1) < 99999` test: 1..99999 means a process; zero means every thread of the current process; all other values are resolved as a thread ID within the current PID. This is a selector branch, not a jump table. The 32-bit check is `if ((uint32_t)(index-6) < 0xfffffff9) return 22`; accepted indices are exactly 0,1,2,3,4,5,0xffffffff. The sentinel branches to six fixed stores before indexed addressing. No code jump table appears.

## Permission and validation checks

The process-selector path calls 0x26d0a8 -> 0x609020 on caller td+0x140; the helper requires cred+0x58 == 0x4800000000010003. Failure returns 3 (ESRCH), hiding the operation. Process lookup 0x53c170 must succeed. The first target thread credential is passed to 0x609890; failure returns 1 (EPERM). The zero and current-process-thread paths contain no equivalent caller credential gate, but target lookup is scoped with the current PID. A missing thread returns 3. Counter values have no configuration-style mask; they are counter contents. Invalid index returns 22 before any store.

## Data flow and locking

uap selector and value -> uint32 range/sentinel validation -> locked process/thread set -> bounded counter_value[6] -> fixed-MSR write helper when enabled -> unlock and errno. The index is zero-extended, but 0xffffffff is handled separately.

## Attack surface and limits

The apparent large-index issue disappears when the unsigned 32-bit comparison is evaluated correctly. Neither 6 nor 255 is accepted. Review remote-update completion, PMU semantics and caller policy, but no out-of-bounds write is established by this index check.

## Interpretation check

The accepted set is 0..5 plus -1 as a uint32 sentinel, not 6..255. Offsets 0x190..0x1b8 are a six-element PMU counter bank, not an extended PTE array.
