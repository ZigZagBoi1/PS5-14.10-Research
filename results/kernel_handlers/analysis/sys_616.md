## Behavior and dataflow

This root returns a bounded name associated with the caller-supplied 32-bit identifier. It first zeros a 0x20-byte local buffer and calls `0xffffffff8b552420(id, current_process+0xbc)`. A successful result supplies a 0x20-byte name at result+0x294; the root releases an object at `*(result+8)+0x148` after copying. The object interpretation as a thread and its +8 pointer as its process is a structural inference, not a recovered symbol.

If the scoped lookup fails, it tests the object at `td+0x140` through helper `0xffffffff8afc8f90`. Independent source-byte inspection at kernel_text RVA 0x608f90 establishes that this predicate returns bit 62 of the qword at credential+0x60. With the bit clear, the root returns 3. With it set, the same lookup is retried using scope -1. If that also fails, `0xffffffff8aefc170(id)` provides a second object; NULL again returns 3. The second object supplies a 0x20-byte name at +0x5e4 and a lock-like object at +0x148.

The fallback has a further visible access gate: `0xffffffff8afc90d0(td->credential)` and bit 1 of byte target+0xb1 together cause release and return 13. Independent bytes at RVA 0x6090d0 show the predicate is exactly credential+0x58 equal to any of `0x4800000000000022`, `0x480000000000002e`, `0x480000000000101f`. These values are evidence; their policy/identity names are unknown.

On either successful path, helper `0xffffffff8ae04eb0(local,0x1f)` determines a length, one byte is added, an accounting-like call `0xffffffff8b5da3e0(gs:0,0xffffffff8bd0f297,0)` runs, and `0xffffffff8ac191d0(local,args+8,length+1)` returns its status. Its independently inspected body validates the user destination range and performs kernel-to-user copy. The length pattern is consistent with a bounded NUL-terminated string of at most 32 output bytes; helper identity remains unlabelled.

## Interface, errors, and attack surface

Arguments are id32 at +0 and user destination pointer at +8. There is no command selector or indirect dispatch. Known local returns are 3 and 13; copy status propagates unchanged. The root does not set `td+0x408`. Stack-protector failure calls `0xffffffff8b0bd6b0` then UD2.

Caller influence is limited to identifier lookup and user output address in this body. Visible name-copy bounds are 0x20, output length bound 0x1f+1. Lock ownership/lifetime guarantees come from the opaque lookup helpers; the release shape alone does not establish them. No unrestricted kernel address write is visible. Distinct thread-name and process-name offsets must not be merged into one structure.
