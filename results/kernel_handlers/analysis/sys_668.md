## Observed behavior and functional interpretation

The true target 0x3af8e0 is a 12-byte wrapper. It clears RSI and tail-jumps to 0x265760. That trampoline forwards to the common 0x5620e0 implementation also used by the nosys map entries 650/651. The declared two argument slots are not read by this wrapper. The common implementation locks process+0x148, clears 112 bytes of local notification state, sets fields 12 and 0x10006, invokes 0x560540(process, thread, 12,&record), unlocks and returns 78. The helper's process/thread traversal and signal masks support a signal-like notification interpretation; exact user-visible delivery needs runtime state.

This description follows the target and the explicitly named linked helpers. Other functions in the attached carrier are adjacent context and are not silently attributed to this syscall. Code observations below are anchored by `ev_fc99bb6787dcc738c22b502b69849b8ff29b74271f0148f9f1c3836ea0a00f8d` and the individual helper evidence in the inventory.

## Dispatch, branches and result semantics

No subcommands or argument decoding occur. The exact target instructions are push rbp; mov rbp, rsp; xor esi, esi; pop rbp; jmp 0x265760 at 0x3af8e7. Neighbor 0x3af8f0 has the same shape but is a separate entry. REA's target-wrapper pseudocode also says halt_baddata because this secondary jump leaves the mapped carrier. The 5 assembly instructions establish the forwarding behavior; the decompiler artifact does not describe an actual halt. Primary evidence: ev_fc99bb6787dcc738c22b502b69849b8ff29b74271f0148f9f1c3836ea0a00f8d.

## Permission and state gates

There is no policy call in this 12-byte wrapper. Policy and return semantics depend on the shared 0x5620e0 routine and upstream syscall dispatch; this local observation does not establish whether all callers are permitted.

## Dataflow, types and side effects

RDI is preserved, RSI is replaced with null, and the tail jump preserves the caller's return path. The pointer originally supplied in RSI is unused here. Common-nosys evidence, when retained alongside this report, determines the final return/error behavior. Assembly 0x562140..0x56214f explicitly sets RSI=thread, EDX=12, RCX=local_record and RDI=process for the helper, even where Ghidra's guessed call omits arguments. The common routine uses live-in RDI although its recovered prototype is void; that prototype is not the syscall ABI.

The analyst interface at the front of `.rea.c` records slot offsets and widths. The remainder is actual REA pseudocode with its warnings retained. Ghidra's guessed prototypes, omitted register arguments, types and synthetic global names require assembly cross-checks; they are not original declarations.

## Attack-surface observations and unresolved contracts

The wrapper itself performs no copy or pointer dereference of user arguments. Its practical reachable behavior is the common unsupported-operation path; large neighboring implementations in the recovered carrier are context, not additional 668 subcommands.

No exploitability finding is made. External helpers, unknown credential semantics, absent mutable data and upstream dispatcher behavior bound the conclusions. A missing check in this local slice is not proof of globally missing authorization. Static control flow does not prove any branch executed.
