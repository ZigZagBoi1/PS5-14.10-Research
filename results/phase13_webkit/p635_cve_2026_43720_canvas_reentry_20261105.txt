Trigger mechanism:
  1. Create canvas, define opts with Object.defineProperty('alpha', {get: ...})
  2. Getter calls canvas.getContext('2d') → sets m_context to CanvasRenderingContext2D
  3. Outer getContext('bitmaprenderer', opts) replaces m_context → frees 2d context (768B)
  4. innerCtx JS wrapper survives → dangling pointer to freed memory
  5. Spray 150 Canvas2D contexts → one reclaims the 768B slot → alias

Key findings:
  - Alias at spray[9] of 150 — early reclaim, high reliability
  - MUST NOT access innerCtx before spray (writing freed memory crashes WebProcess)
  - All Canvas2D state properties alias bidirectionally
  - Pixel data (getImageData) is per-canvas, not per-context — not shared through alias
  - stateStack OOB read does not work — reclaim reinitializes m_stateStack
  - 150 × 1×1 canvases stay within PS5 browser memory budget
  - WebKit fix: commit 2693828e8d73 (2026-06-29), NOT present in PS5 14.10 (build Sep 2026)

Primitive gained:
  State R/W channel: 48 bytes via transform (6 doubles) + lineWidth, miterLimit,
  globalAlpha, shadowBlur, shadowOffsetX, shadowOffsetY, lineDashOffset (7 doubles).
  fillStyle (string). save/restore stack operations through alias.

  This is a CONTROL primitive, not an info-leak. Float64 properties are subject to
  DAZ (Denormals Are Zero) — userland pointers read as 0 through doubles.
  Integer byte access via getImageData returns per-canvas pixels, not context state.
