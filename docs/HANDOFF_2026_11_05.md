## 0. Console access

**Target: 192.168.1.121, TCP port 9026.** Same LAN as the workstation (192.168.1.0/24). No auth, no handshake.

- **What listens there:** a Lua 5.1 loader embedded in the running PS5 game/app. Every accepted TCP connection **spawns a fresh process**, so ASLR and every heap address change per connection. Never hardcode an address across runs.
- **Protocol:** send the Lua source as **raw bytes** - no length prefix, no framing (CLAUDE.md says 8-byte LE length prefix; the loader on 14.10 does not; send_probe.py sends raw and works). The loader compiles and runs it, streams print() output back on the same socket, and closes.
- **Reply terminator:** no protocol framing either. Read until the socket closes or until the marker string the probe prints (each probe ends with "=== DONE <name> ==="). If no DONE marker appears, the process died rather than finished - that is the signal for a crash.
- **Readiness probe:** a plain TCP connect. Closed port = loader down = the console needs the game relaunched (crash recovery is manual: relaunch the app, the loader comes back on the same IP:port). Automated waiting:

      import sys; sys.path.insert(0,'tools')
      from send_probe import wait_for_loader, send_lua
      wait_for_loader('192.168.1.121', 9026, timeout=7200, poll=2.0, log=print)
      send_lua('192.168.1.121', 9026, 'probes/phase17_new_vectors/<probe>.lua', save=True, timeout=180)

  .local/run_queue.py already wraps this for a list of probes; that is how a relaunch gets used without hand timing.

- **Sending one probe:**

      cd C:\PS5contrib
      python tools\send_probe.py --ip 192.168.1.121 --port 9026 probes\phase17_new_vectors\<probe>.lua --save --timeout 240

  --ip matters: the default is 10.0.0.96 and will silently fail. Results land in results\<phase>\<probe>_<timestamp>.txt and the console echoes status COMPLETE / TIMEOUT.
- **PowerShell-only alternative:** .\tools\send_probe.ps1 probes\<phase>\<name>.lua -Save
- **Recovery cost:** a wedged loader needs a game relaunch (minutes, manual, user-driven). A hard crash can also cost a console reboot. Treat every probe that dereferences, executes, or writes kernel state as potentially the last run of the session - order the queue cheapest-and-safest first, fatal last.
- **Firmware / kernel:** fw 14.10, FreeBSD r230171 (Sep 28 2026), 16 KB pages, Zen 2 APU (Oberon, hw.model 100-000000189).
- **Loader API surface used by probes:** syscall.pipe (+ make_syscall(n) to bypass the Lua name filter), memory.alloc / read_byte / read_dword / read_qword / write_byte / write_dword / write_qword, native.fcall_with_rax(fn, rax, rdi, rsi, rdx, rcx, r8, r9), get_error_string(), uint64(), dynlib_get_info(593). There is **no** memory.get_addr and no cpu_features/cpuid/rdtsc export.

## 1. Tooling rules that cost hours

- **Capstone: start on a known instruction boundary.** Decoding 0x3cb650, 0x3cb8d0, 0x8fb0c0 produced garbage (xor cl,[rax+0x3b]). Sweep linearly from a function start and filter by address.
- **Capstone relative targets are signed.** Mask ins.operands[0].imm with 0xffffffffffffffff before subtracting BASE, or every call target comes out negative and a census returns zero rows (this happened).
- **The loader's Lua is 5.1:** no //, no & | << >>, no goto, no memory.get_addr. Use math.floor(a/b) and arithmetic bit tests; memory.alloc(n) returns a uint64, take its address with tonumber()/N().
- pcall everything; errno strings are stale on success.
- Non-blocking socket read is recvfrom(29) with 0x80 (MSG_DONTWAIT). 0x40 is MSG_WAITALL and wedges.
- One image-wide capstone job at a time - six concurrent full-image decodes froze the machine for 29 minutes.
- Lua fill patterns must stay below 2^53 or uint64->double rounding silently changes them.
- Static image: docs/dumps_13.60/kernel_text.bin, base 0xffffffff8a9c0000, **file offset == RVA**, length 0xE6E5C0 (text only; anything past it, including the dmem container table at ~0x34D0E50, is absent).
- Kernel base per boot: probes/phase17_new_vectors/1001a_kernel_map_sweep.lua (512 thr_create children, fault blob magic 0x13371337, #PF error tells present vs absent). DMAP base 0xffff800000000000.

## 3. Live leads, ranked

1. **probes/phase17_new_vectors/1248a_exec_page_hunt.lua** - file-backed MAP_PRIVATE mapping of /app0/eboot.bin. PROT_EXEC dropped for MAP_ANON does not imply dropped for a vnode; a COW mapping would also be writable. **Fix first:** line 78 uses &, replace with arithmetic.
2. **probes/phase17_new_vectors/1249a_sys607_path_oracle.lua** - 607 returns a 0x88 block (static .data pointer, vnode, cred, td) but only if cred+0x58 == 0x4800000000000010, else 0x609c00 zeroes it. **Fix:** remove uint64.get_addr.
3. **probes/phase17_new_vectors/1250a_shm_faultin_and_exec.lua** - 629 is shm_open, not physhm (0x91BCA0: name list + strncmp, [proc+0x5c0]/[proc+0x5d0], flags subset of 0x200203). Retests 1240a's "PTE absent" claim: FreeBSD copyin does not fault pages in, so EFAULT on a demand-zero page is expected. User-touch first.
4. **0x350cd0** pops a list treating +0x1a0 as a pointer; 566 writes +0x1a0 on [thread+0x3f8], which does not alias [proc+0x200] in 13.60. If 14.10 merges layouts, syscall(566,0,-1,KADDR) plants a pointer in a popped list head = kernel write.
5. **0x259b35** - full generic wrmsr(msr,value) with zero callers image-wide. Re-check on newer firmware.
