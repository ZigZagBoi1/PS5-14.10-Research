## Behavior and data flow

At `0x705880`, first tests two credential predicates, then reads requested size from argument +8 and flags from +0x10. Requires 0x4000 alignment and no flags outside 0x37. Creates a VM-object-like allocation through `0x45da60`, using caller credentials and process allocation/context fields +0x5c0/+0x5d0. Charges the requested size through `0x2c5d00(...,2,size)`. Allocates a 0x58-byte region descriptor plus a one-byte-per-16-KiB-page counter array. Under the global list lock at 0x39202e8, finds a sufficiently large gap in the list rooted at 0x39202f0 and inserts the new region with start/end and reference state. A credential-dependent flag-0x4 path contributes size to the global charged total at 0x39203a0, capped at 0x4100000. Builds a 0x18-byte descriptor payload containing VM object, region and flags, configures VM-object flags and stores the region pointer at object +0x160. Allocates a file/descriptor through `0x72c7a0`, publishes file type **0xe**, marks the descriptor’s table entry under lock, drops the temporary file reference, and returns the integer descriptor through `td + 0x408`. Failure paths undo budget/object/payload state. Argument slot 0 is not consumed by the visible body.

## Dispatch and subcommands

No user subcommand switch, jump table or user function pointer. Flags are configuration bits constrained to mask 0x37. Flag 0x4 influences the special/accounted path; the selected credential checks determine whether that path contributes to the 0x4100000 cap. Gap selection is a linked-list traversal, not a dispatch table. A fixed operations-table address 0x2202e88 is passed when publishing file type 0xe; its contents are outside the available imported code, so individual file-operation slots are not recovered.

## Permission checks and validation

**Explicit credential gate:** either `0x6095c0(td->credential)` or `0x609620(td->credential)` must be nonzero; otherwise returns 1. Size alignment and allowed flag mask are checked before allocation. Additional predicates 0x609540/0x609560 govern the special flag-0x4 accounting choice. Global list/total mutation is locked, and reference changes use atomic instructions. An exhausted backing gap/cap and several allocation failures return 0xc. The zero size is aligned and no explicit nonzero-size test appears in this body; backend behavior still applies.

Recovered helpers refine this gate: 0x6095c0 accepts credential capability-word +0x68 bit 62; 0x609620 accepts bit 61. Both also allow capability bit 56 when platform helper 0x5a4c20 succeeds, or identity high byte 0x41 when platform helper 0x5a59f0 succeeds. The platform helpers are external, so their policy is unresolved. The flag-0x4 accounting predicates additionally combine capability bits 61/62 with credential byte +0x82 bit 7.

## Attack surface and limits of conclusions

Primary boundaries are privileged resource allocation, 64-bit size/accounting, shared backing-region lifecycle, descriptor publication and object/file reference rollback. The per-page array size is `size >> 14` after alignment. Review size zero and very large sizes against allocator, accounting and list arithmetic contracts; no concrete overflow is established here. There is no user buffer copy or raw kernel-address result. Returning an integer descriptor does not disclose the backing-object pointer. The global cap is conditional accounting, not a universal maximum allocation size.

This is static analysis of a recorded kernel image. A missing check in this body does not establish that the syscall entry path, object namespace, or external callees impose no checks. Review points are not confirmed vulnerabilities or exploit primitives. No target code was executed.
