## Behavior and data flow

At `0xc16020`, validates attributes and signed initial/maximum counts, bounded-copies a user name, allocates a fixed `0x60`-byte object, and initializes it through `0xc155a0`. Initialization records current and initial counts, maximum, lock/wait channel, empty waiter list and attributes. Reserves a caller-namespace handle; bit 0x100 additionally registers name/object with type 0x120 and initializes shared references to 1. Stores creator PID at object +0x58. Success publishes the handle and stores it at `td + 0x408`; handle exhaustion returns 0x23. Name-copy and registry errors unwind the handle/name/object.

## Dispatch and subcommands

No user-selected function table or selector switch in the entry. The related type-0x120 operations are create 549, delete 550, open 551, close 552, wait 553, poll/try-wait 554, post/signal 555 and cancel/reset 556. Names describe recovered behavior and are not original symbols.

Allowed attribute bits are `0x103`; low bits 3 are rejected and low bits 0 default to 1. Shared-name registration is controlled by bit 0x100.

## Permission checks and validation

No direct entry privilege gate. Explicit validation requires `initial >= 0`, `maximum > 0`, `initial <= maximum`, non-null name, bounded 0x20-byte name copy, and allowed attributes. Registry collision/access semantics remain in external registry routines.

## Attack surface and limits of conclusions

Review shared naming, handle-exhaustion rollback and lifecycle/refcount behavior with open/delete/close. Counts are low-32-bit signed values; the initializer’s fields prevent treating the initial count as an unchecked allocation size. Object and name allocations have fixed sizes.

This is static analysis of a recorded kernel image. A missing check in this body does not establish that the syscall entry path, object namespace, or external callees impose no checks. Review points are not confirmed vulnerabilities or exploit primitives. No target code was executed.

## Recovered types

Four syscall slots. Count and attributes fields consume only the low 32 bits. Object initialization establishes count offsets 0x40/0x48/0x4c and attributes 0x44; shared-reference state is at 0x54.
