# Handler 563: Enable per-thread performance monitoring

## Identity and scope

- Sysent metadata: 1 arguments; mapping classification `real`.
- Runtime base from supplied context: `0xffffffff8a9c0000`; all addresses below are RVAs.
- Primary analyzed body (inclusive): 0x602fe0..0x603142, 0x603150..0x603250.
- The full `.asm` covers all 4,096 source bytes, plus primary implementation and selected support. Neighbor trampoline targets are not part of this syscall.

## Behavior

For each selected thread, sets bit 22 (0x400000) in six saved event-control words at MD/PCB offsets 0x160..0x188, sets thread+0x380 to 1, and calls RVA 0x602d40 to apply or synchronize the change. Already-enabled threads are unlocked without reprogramming. No user buffer is copied.

## Dispatch and subcommands

The low 32-bit selector is interpreted by an unsigned `(selector-1) < 99999` test: 1..99999 means a process; zero means every thread of the current process; all other values are resolved as a thread ID within the current PID. This is a selector branch, not a jump table.

## Permission and validation checks

The process-selector path calls 0x26d0a8 -> 0x609020 on caller td+0x140; the helper requires cred+0x58 == 0x4800000000010003. Failure returns 3 (ESRCH), hiding the operation. Process lookup 0x53c170 must succeed. The first target thread credential is passed to 0x609890; failure returns 1 (EPERM). The zero and current-process-thread paths contain no equivalent caller credential gate, but target lookup is scoped with the current PID. A missing thread returns 3.

## Data flow and locking

uap.selector -> process/thread resolution -> process and thread locks -> saved event_select[0..5] and pmc_state -> local hardware programming or remote CPU synchronization -> errno. The helper uses scheduling state ==4, GS current-thread comparison, pending state bits, an interprocessor request and a pause loop.

## Attack surface and limits

The relevant surface is per-thread PMU state, scheduling, and cross-CPU synchronization. Review lock ordering, target thread lifetime and synchronization completion. A local-path credential gate is absent in the visible handler; that alone does not establish a permission bypass. Six fixed slots are touched; no user-selected kernel address, PTE manipulation, or arbitrary-write primitive is demonstrated.

## Interpretation check

The fixed MSR programming routines at 0x602830 and 0x6029e0 identify this family as performance monitoring. The saved words are not evidenced as page-table entries.
