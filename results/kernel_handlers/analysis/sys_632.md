## Behavior and observed layouts

Body `0xffffffff8adf8e30`–`0xffffffff8adf9061` reads one u64 identifier at argument `+0`. Equality to sign-extended caller u32/s32 `+0x9c` returns 11. Lookup `0xffffffff8b552420(identifier, u32(*(caller+8)+0xbc))` returns an object or NULL (return 3). The object has pointers `+0` and `+8`, u32 flags `+0xe4` and `+0xe8`, and u32 state `+0x400`. Caller and target likely represent thread-like objects with parent/process scope, an inference from self-ID check and paired flag/state operations shared with 633/634; exact type names are not recovered.

After `0xffffffff8ae878b0(target,0,0xffffffff8bcd1b07,0x32f)`, an existing `+0xe8 & 0x20` or negative signed `+0xe4` returns 22 through two release-like helpers (`0xffffffff8ae87520(*(target+0)+0x18,0,0,0)` and `0xffffffff8ae86fa0(*(target+8)+0x148,0,0,0)`). If both `+0xe8 & 2` and `+0xe4 & 8` are set, it sets state to 1 and `+0xe8 |= 0x20`, then returns 0.

Otherwise `+0xe4 |= 0x80000800`. State 4 additionally calls `0xffffffff8b4c35d0(target)`. A loop at `0xffffffff8adf8ef0` continues when state is 3/4 or `+0xe8 & 8`: release helpers, call `0xffffffff8b5c6830(global-address, global-value, 0, 0x100)`, then repeat lookup using **low u32** of the original ID. NULL returns 3; a changed object pointer returns 3 after the parent-release-like call on the replacement object. The same object is reacquired with line constant `0x34f`. When flag bits 2/8 become jointly set, `+0xe4 &= 0x7ffff7ff`, state becomes 1 and `+0xe8 |= 0x20`. If neither loop condition holds, it simply releases and returns 0.

## Checks, returns and attack surface

No command selector, direct caller-buffer transfer or explicit authority predicate is visible. The scope argument to lookup, self-ID rejection, and target-state preconditions are the visible restrictions; any permission semantics in lookup remain unknown. Numeric returns: 0, 3, 11, 22. State/flag mutation with release/relookup loops, object identity replacement and full-width-to-u32 identifier change are the primary review surfaces. A wait/suspend-like interpretation is plausible, not a proven syscall name. No race or privilege flaw is established by this wrapper alone.
