## Behavior, state dispatch and layout

Body `0xffffffff8adf9150`–`0xffffffff8adf9396` loads low u32 identifier at argument `+0` and output pointer u64 at `+8`. It looks up through `0xffffffff8b552420(id, u32(*(caller+8)+0xbc))` and obtains the same partial target type as 632/633: pointers `+0/+8`, flags u32 `+0xe4/+0xe8`, state u32 `+0x400`.

After acquiring through `0xffffffff8ae878b0(...,line=0x390)`, it requires at least one of caller byte `+0x529 & 1`, target `+0xe8 & 0x20`, or target signed `+0xe4 < 0`; otherwise it releases and returns 22. These are exact flag gates; no known permission-bit name is asserted. The state switch begins `0xffffffff8adf91e5`: 2/3/4 release, call `0xffffffff8b5c6830(...,0x100)` and relookup; NULL yields 3. State 0 releases and returns 3. State 1 permits extraction. Other states take diagnostics at `0xffffffff8adf935c`, call `0xffffffff8b1b1950`, `0xffffffff8b1b18a0`, `0xffffffff8b65aa10`, then UD2.

For state 1 it invokes zeroing-like `0xffffffff8ac18ff0(snapshot,0x500)`, then `0xffffffff8b3cbb60(target,snapshot+0x40,0)`. After two release-like helpers, it invokes `0xffffffff8b5da3e0(current,0xffffffff8bd0f297,0)` and transfers through `0xffffffff8ac191d0(snapshot, user_output, 0x4c0)`, returning that helper's result. The destination passed to the extraction helper is **snapshot+0x40**, but transfer starts at **snapshot base**, length **0x4c0**. No further snapshot sublayout is proven. Stack guard checking protects the actual 0x500-byte local.

## Surface and limits

This resembles a stopped-target snapshot/context read by state relationships, but exact content and syscall identity remain unknown. Visible errors are 22 for failed flag gate, 3 for missing/dead state, plus transfer result; unexpected internal state and stack-guard failures enter fatal paths. The principal surfaces are target-ID scope, state wait/relookup behavior, fixed-size extraction at an interior local-buffer offset, and a fixed 0x4c0-byte output transfer. Helper-body review is needed to establish write bounds and initialization coverage; no uninitialized leak or overflow is demonstrated by these calls alone.
