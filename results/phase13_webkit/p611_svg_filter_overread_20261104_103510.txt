--- Analysis ---

T0 (CTRL): 4096 = 64x64. Red rect rendered correctly to canvas via Blob→Image→drawImage.
Confirms the SVG→canvas pipeline is functional on PS5 WebKit.

T1 (OFFSET-128): feOffset shifts the 64x64 rect to (128,128). The area at (0,0)-(128,128)
should contain heap data if the filter's output buffer wasn't zeroed. nz=4096 means ONLY the
shifted rect has non-zero pixels. The vacated area is clean transparent. Buffer is zeroed.

T2 (BLUR-50): feGaussianBlur with stdDeviation=50 on an 8x8 rect at center. The Gaussian
spreads so thin across 256x256 that all values round to 0 in 8-bit color. The key finding:
nz=0 AND nza=0 — even the ALPHA channel is zero everywhere. The 256x256 output buffer
(256KB) is fully zeroed. No heap residue.

T3 (CONVOLVE-EDGE): ★ KEY TEST. 21x21 kernel with all weight at position (0,0), targetX=10
targetY=10. For pixels near the filter region edge, the kernel reads 10 pixels OUTSIDE the
filter region boundary. With edgeMode=none, these OOB reads should return (0,0,0,0).

Result: 2116 = 46x46. The filter region is 56x56 at (100,100). For pixels at positions
x=0..9 or y=0..9 within the filter region, the kernel's (0,0) weight falls outside the
buffer → edgeMode=none returns 0 → output is transparent. Only pixels at x=10..55,y=10..55
(46x46 = 2116) receive the source color from the shifted kernel.

This EXACTLY matches the spec: OOB kernel positions return 0, not buffer data. No heap read.

T4 (CONVOLVE-CTR): Control for T3. Same 56x56 filter region, identity kernel (weight at
center). All 3136 = 56x56 pixels reproduce the input. Confirms the convolution setup works
and T3's reduced count is from the OOB shift, not a rendering bug.

T5 (MORPH-32): feMorphology dilate with radius=32 on a 16x16 rect at (100,100). Dilation
expands the source by 32px in each direction → (100-32,100-32) to (116+32,116+32) = 80x80.
nz=6400 = 80x80. The expanded area is all source color (red), not heap data. The dilation
kernel correctly propagates the source color to expanded edges.

T6 (TILE-7): feTile with a 7x7 rect. The primitive's input subregion is the full filter
region (256x256), so the tile is the 256x256 buffer with 7x7 red at origin. Tiling 256x256
into 256x256 = one tile → 49 pixels. The test doesn't exercise partial-tile edges as
intended (would need explicit primitiveUnits), but still confirms: no excess non-zero pixels
in the 65536-pixel scan.

T7 (OFFSET-MERGE): feOffset + feMerge with an empty first MergeNode. The empty node references
the default SourceGraphic but at its original position (not shifted). feMerge composites two
layers. nz=4096 = only the shifted rect. The merge operation's buffer allocation is zeroed.

--- SVG Filter Surface: EXHAUSTIVELY DEAD ---

All six filter primitives tested (feOffset, feGaussianBlur, feConvolveMatrix, feMorphology,
feTile, feMerge) produce correctly initialized output buffers with zero heap residue.

The feConvolveMatrix edgeMode=none test (T3) is the strongest discriminator: it forces kernel
reads 10 pixels outside the filter region boundary. The implementation correctly returns zeros
for OOB positions rather than reading adjacent buffer memory.

Combined with p609/p609b (WebP) and p610 (PNG):
- Image decoders: ALL buffers zeroed (WebP, PNG truncation, PNG filter, PNG palette OOB)
- SVG filters: ALL buffers zeroed (offset, blur, convolution, morphology, tile, merge)

The PS5 WebKit port zeroes every allocation tested. Neither image decoder buffers nor SVG
filter intermediate buffers contain heap residue. These surfaces cannot be used as heap read
primitives for WebProcess text base discovery.
