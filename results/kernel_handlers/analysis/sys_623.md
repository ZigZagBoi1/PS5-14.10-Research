## Behavior and checks

The root first calls `0xffffffff8afc8f90(*(td+0x140))`. Independently inspected source bytes at kernel_text RVA 0x608f90 establish the predicate as `(*(uint64_t *)(credential+0x60) >> 62) & 1`. A clear bit returns **1** immediately. This is an exact visible permission-like gate; its policy name is unknown.

On acceptance it initializes a 32-bit local to zero. It calls global predicate `0xffffffff8b48ce10`; when true, `0xffffffff8b028540(&local)` is invoked, but its error return is ignored. The root then calls `0xffffffff8b5da3e0(gs:0,0xffffffff8bd0f297,0)` and copies exactly four bytes to user pointer `*(args+0)` using `0xffffffff8ac191d0`, returning that copy status.

Supplemental setter/getter inspection confirms this is the read counterpart of handler 617. The getter loads global `0xffffffff8e1e9a60`; NULL returns 6 without writing the output. With a non-NULL output pointer it locks object+0x28, loads descriptor=`*(object+8)` and base=`*(descriptor+0x10)`, and reads dword base+0x25310 when descriptor+8 is nonzero, otherwise executes `in eax,dx`. It unlocks, translates low nibbles using table `0xffffffff8bd79ee0`, and combines the translated low byte with the remaining high24 bits before storing the local. The translation bytes and hardware meaning are unavailable.

The global predicate's verified source flow is `!sub_...8afa2da0() && (sub_...8afa2cc0() || sub_...8afa30c0()) && !(global_u32[0xffffffff8e681390]&1)`. This supplements but does not identify the credential gate.

## Errors and attack surface

The syscall takes one user output pointer, has no subcommand selector, and does not write the thread's syscall-return slot. If the global predicate is false, zero is copied successfully when the destination is valid. Getter errors can also leave the initialized zero and are hidden by the root. Known local rejection is 1; copy errors propagate. Stack-protector mismatch invokes `0xffffffff8b0bd6b0` and UD2.

The surface exposes a four-byte hardware-derived value only after the credential bit test. The user chooses output location but not the hardware base/offset. The inspected kernel-to-user copy routine validates destination range. Hardware-read failures and conditionally unavailable hardware are indistinguishable from a true zero at this root.
