# GPU and VM syscalls on 14.10 (probes 93a, 98a, 99a, 942a, 942b, 114a)

These probes test the claim, taken from the 13.60 capture decompiles, that six
syscalls reach page tables or hardware without a credential predicate:

| syscall | 13.60 claim |
|---|---|
| 654 | single 64 KiB-aligned VM range operation on type-11 objects |
| 655 | range reset companion |
| 657 | batched VM commands, 0x20-byte records, opcodes 1-5 |
| 653 | PTE attribute modification, mask check on arg0 only |
| 617 | one-byte hardware register write through a lookup table |
| 620 | VM operation (mode 5) on the page holding the caller's return address |

All were run on 14.10 with a live GPU mapping created through `mmap` (477).
None changed protection, produced an executable page, or moved the VM counter
(624).

## Measured results

| probe | call | result |
|---|---|---|
| 93a | 654 `(addr, len, op 0/3/10..15, flags, 0)` | `-1` for every operation |
| 93a | 655 `(addr, 64 KiB, 0)` | `-1` |
| 93a | 657 `(records, n, out, 0)` opcodes 1-5 | `-1`, `processed=0` |
| 98a A | 547 `(addr, out)` on a GPU mapping | `0`; see layout below |
| 98a B | 653 `(arg0)` | see "653" below |
| 949b/949c | 653 with 1, 2, 3 and 6 arguments, selectors 0..0x4000000 | `-1` in every shape |
| 99a A | 617 `(byte)` for 0x00..0xFF and wide values | `0`, VM counter unchanged |
| 99a B | 620 `()` and five repeats | `0`, VM counter unchanged |
| 114a A | ten GPU mappings | adjacent, 0x10000 apart, no guard page |
| 114a C | `MAP_FIXED` inside a GPU mapping | replaces it; replaced pages read back zero, neighbours intact |

The GPU pages themselves stay readable and writable after every call, so the
`-1` results are not a consequence of the mapping going away.

## sys 547 record layout (14.10)

`547(address, out)` returns `0` and writes three qwords:

```
+0x00  region start
+0x08  region end
+0x10  0x61002000000033   (GPU mapping)
+0x10  0x0000000000000003   (anonymous heap mapping)
```

The low half of the third qword is the protection word as the kernel records it
(`0x33` for a GPU mapping, `3` for heap). The high half differs between the two
kinds and is the only field that distinguishes them; it is not a type number
from the type-11 test the 13.60 handlers use.

## sys 653: one unambiguous contradiction

The first run of 98a section B, in a process that had just created a GPU
mapping, returned small positive codes for the three selectors the mask allows:

```
arg0=0x000000  ret=22
arg0=0x100000  ret=23
arg0=0x400000  ret=640
arg0=0x500000  ret=-1
arg0=0x000001  ret=-1
arg0=0x0000FF  ret=-1
```

Every later run, including 98a section B itself replayed on a fresh process and
949b/949c in all argument shapes, returned `-1` for the same three selectors.
The 13.60 body's default return is `0x16` (22) and the success path returns a
dword read from the thread at `+0x5d0`, so 22/23/640 are consistent with a
thread-state read rather than a capability change, but the reason the values
appeared once and never again is unresolved. No probe has shown 653 modifying
protection of any page, and `mprotect` still fails after it.

## What this rules out

- 654, 655 and 657 do not accept a GPU mapping made by `mmap(477)`. Whatever
  object type their type-11 test wants, a userland GPU mapping is not it, and
  the entry path rejects the call before any range work.
- 617 and 620 return success and do nothing measurable: the VM counter does not
  move, and no protection state changes. They are the same shape as 605 and
  675, which also return `0` without an observable effect.
- `MAP_FIXED` over a live GPU mapping is handled cleanly: the old mapping is
  torn down, the replacement is zero-filled, and neighbours are untouched. No
  stale physical page survived into the replacement.

None of the six is a W^X bypass.

## Reproducing

Section wrappers for these probes are generated by prepending the section
selector to the probe file, for example:

```sh
{ echo 'TEST_SECTION = "C"'; cat probes/phase17_new_vectors/98a_gpu_pte_wxbypass.lua; } > /tmp/98a_secC.lua
python tools/send_probe.py --ip <console> --save --metadata /tmp/98a_secC.lua
```
