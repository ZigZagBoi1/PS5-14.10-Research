## Behavior and data flow

Requires a signed-positive count at argument +8, looks up type 0x120, and calls `0xc15aa0(object, count)`. It releases the lookup and returns the helper’s status. Nonpositive counts return 0x16 before lookup; missing handles return 3. The helper implements capacity/count update and waiter wakeup rather than the wrapper directly adding an unchecked value.

Recovered post helper locks +0x18, computes a machine 32-bit sum, and rejects a negative result or a result above maximum with 0x16. Otherwise it stores the sum, removes satisfied queued waiters while consuming their requested counts, and wakes them. For valid nonnegative current_count and positive input, a signed-overflowing sum becomes negative and is rejected by the machine check. The pseudocode’s signed C expression must not be interpreted as evidence of C-level undefined behavior in the binary. Closed/deleted objects take a no-change success path.
