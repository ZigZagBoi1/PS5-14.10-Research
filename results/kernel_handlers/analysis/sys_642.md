## Observed behavior and recovered layout

Body `0xffffffff8b47dad0–0xffffffff8b47e1be` enumerates a selected object's linked map entries and creates 0x68-byte records. Args are signed ID dword +0, signed capacity dword +8, record-array pointer +0x10 and mandatory count-output pointer +0x18. The low dword is used in the first two syscall slots; upper bytes are not read.

Record offsets: 0x00 bounded 32-byte text from entry+0x150; 0x20/0x28 range endpoints; 0x30 sign-extended 32-bit XOR token; 0x38 attributes; 0x3c/0x40 backing dwords +0x130/+0x138; 0x44 page-map presence count; 0x48 backing type; 0x4c/0x50 absence/callback counters; 0x54/0x58 page+0x70 nonzero/zero counters; 0x5c page+0x66==1 counter; 0x60 additional page category counter; 0x64 sign-extended entry byte +0x14c. Recovered C documents exact source offsets. These are use-based labels, not verified public types.

After ID lookup `0xffffffff8aefc170`, null returns 2. Flag 0x2000 in owner+0xb0 also releases owner+0x148 and returns 2. Otherwise it increments owner+0x358; flag 0x10000000 controls call `0xffffffff8aefaa10`. It releases owner+0x148, locks map=owner+0x200 through `0xffffffff8ac86820`, and traverses from map+8 until the sentinel. Entries with word +0x66 zero or flags +0x60 bit 1 set are skipped. Backing types 3 and 4 are skipped after backing lock acquisition. Attributes derive from entry+0x64 with flags 0x20/0x1000 translated to 0x10000/0x20000. A null backing pointer zeroes the entire record before the text copy, including previously filled range/attributes.

For backed entries, pages are rounded and scanned in 0x4000-byte units; `0xffffffff8b29e3e0(map+0x1d8,address)` contributes nonzero presence counts. Per-page object lookups use `0xffffffff8b5497e0` and shadow chains at backing+0xb0, adding backing+0xb8 offsets. Found pages call `0xffffffff8b54d8a0` and contribute counters from page+0x70 and byte +0x66. Missing-page paths can walk shadow chains again to invoke a backing-type-1 callback. Kernel object locking uses `0xffffffff8b1946a0` / `0xffffffff8b194eb0` with object+0x18. Exact branch predicates and counter assignments are preserved in recovered C. The token is signext32(low32(backing) XOR 0x8e5b6e18), where the constant is the low address of global `0xffffffff8e5b6e18`; this is not the raw pointer and not demonstrated cryptographic anonymization.

Text transfer at `0xffffffff8b47e04e` calls `0xffffffff8b317b70(destination,entry+0x150,0x20)`. Raw helper bytes at `0xffffffff8b317b70–0xffffffff8b317bc3` (RVA 0x957b70) corroborate strlcpy-like behavior: copy at most 31 source bytes, NUL-terminate, continue scanning the source to determine full length, and leave destination bytes after the terminator unchanged. The record is zeroed once before the loop (and again for null backing); thus trailing text bytes can retain bytes from the previous record, while initial stack garbage is not established. Eligible entries are counted even when array pointer is null or capacity has been reached. Array copy uses `0xffffffff8ac191d0` with destination base + 0x68*signext(count), only when count<capacity. A nonzero row-copy result breaks enumeration before incrementing count, then cleanup proceeds. It unlocks the map, decrements owner hold count under owner+0x148, and may wake at `0xffffffff8b5c6910` when count becomes zero and owner flags include 0x2000.

## Returns, attack surface, and limits

After cleanup a mandatory 4-byte count copy overwrites the register carrying a prior row-copy error. Its result is returned unless records!=NULL and signed count>capacity, which forces `0x0c`. Thus row-copy failure can lead to a successful final return when the count copy succeeds; the returned count excludes that row. This is observed control flow, not an asserted security defect. Before every user copy `0xffffffff8b5da3e0(gs:0,0xffffffff8bd0f297,0)` is called with return ignored. Canary mismatch calls `0xffffffff8b0bd6b0`.

User controls ID, signed capacity and two output destinations. Null array supports a count-only traversal; null count destination is still passed to the copy helper. Capacity does not bound traversal or per-page work. Kernel mapping sizes, list/shadow-chain integrity and object lifetime are trusted; huge-range arithmetic and signed page-index truncation are visible but not shown user-exploitable. The record exposes address ranges, object-derived tokens, text and counters behind the bit predicate. Copy pointer checks, lookup cross-object policy, helper side effects and callback implementation need separate analysis. No runtime exploit or permission bypass is established.
