=== DECODE ===

WIDTH IS EXONERATED. The v921 B1 rejection (w=64, no IDAT) was confounded by
my fcTL delay=0/10 (the kit uses 1/100; a strict parser rejects delay_num=0).
With kit-faithful fields, even a 64-pixel-wide APNG without a default image
kills the WebProcess.

FINAL KILL SIGNATURE (v920 run 2 + v921 + v922 + v923):

  An APNG accepted by the decoder whose chunk stream contains NO IDAT
  (no default image) — fcTL followed directly by fdAT — kills the
  WebProcess during frame decode, on 14.22 and (per the board's P674B
  13/13) on 14.10, with:
    - any width (64..16384) and any frame data (valid zlib, corrupted
      zlib — v922 M1 — both die),
    - any dispose/blend (v922 M2/M3),
    - and requires the animation pipeline (num_frames>=1 — v922 M6
      rejects cleanly) and fcTL.w == IHDR.w (v922 M4/M5 reject on
      mismatch).

TRIGGER CLASS: the frame pipeline derefs the missing default image — the
fcTL seq=0-without-IDAT sequence makes the decoder process a frame whose
default-image buffer was never created. Death site is data-independent =>
most consistent with a null/missing-buffer deref at a fixed decoder site
(DoS grade) UNLESS the console crash module+offset entries show a write.
