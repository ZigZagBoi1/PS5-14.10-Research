## Behavior and argument layout

Body `0xffffffff8b2dc640`–`0xffffffff8b2dc73c` is a four-slot wrapper with a sentinel-or-path first argument. Exact loads are first u64 at `+0`, u32 at `+8`, u16 at `+0x10`, and u32 at `+0x18`. Literal first value 1 branches at `0xffffffff8b2dc652` directly to `0xffffffff8b2dc6f8`, using literal 1 in the delegate's second argument. Every other first value is treated as an input pointer: a 0x400-byte allocation is requested from `0xffffffff8b5c8b50`, then `0xffffffff8ac19900(pointer, buffer, 0x400, 0)` is called. The latter is inferred to be a bounded user-string transfer; its precise fault/termination semantics require its body.

A successful transfer requires first byte `/` (`0xffffffff8b2dc6a4`). If `0xffffffff8afc92d0(caller+0x140)` is nonzero, `0xffffffff8b291a30(buffer, 0xffffffff8c1dd494, 12)` must return zero; otherwise diagnostic `0xffffffff8b1cd5a0` runs and the wrapper returns 2. The 12 bytes at that address are not present in the supplemental ELF, so their text and comparison helper identity remain unknown. An opaque conditional path-prefix policy is inferred, without assigning a known authority predicate.

## Delegation, returns and surface

At `0xffffffff8b2dc715`, `0xffffffff8b2dbca0(caller, path_or_literal_one, arg1_u32, arg2_u16, arg3_u32, 0)` supplies the operational result. `0xffffffff8b5c8df0(buffer, 0xffffffff8cf11e10)` is then called, including buffer=NULL on the sentinel path. Nonabsolute paths return 22; the conditional prefix rejection returns 2; transfer and delegate errors propagate. No additional subcommand switch is visible.

Caller-controlled strings (up to 0x400 per the call), sentinel interpretation, truncation of later slots, conditional prefix policy, allocation/cleanup, and the unreviewed delegate form the attack surface. No vulnerability is proven. Allocation failure is not explicitly checked in this wrapper; allocator flags/body determine whether a null return is possible. There is no evidence that the neighboring tree-manipulation function beginning `0xffffffff8b2dc740` belongs to this syscall.

## Additional direct-helper evidence

The first four are encoded as unsigned subtraction from `0x4800000010000004`, range 0..15 and bitset `0xe001`. This is an observed identity-value membership test. An auth-ID-like interpretation is plausible from its caller's `+0x140` object, but no external naming or ownership of those values was corroborated. These helper bytes come from supplied kernel text directly, outside the selected-body ELF.
